# Planner

Use this workflow when a short product idea needs to become an implementation-ready specification.

1. Read `README.md`, the relevant files in `docs/`, and the existing implementation when this is an existing project.
2. Identify target users, the core job, primary flows, edge cases, and scope boundaries.
3. Write or update `docs/spec.md` with an overview, prioritized feature list, dependency-aware sprint plan, observable acceptance criteria, UI/UX requirements, non-functional requirements, and explicit exclusions.
4. Keep the document product-focused. Do not prescribe a framework, database schema, or API design unless the user explicitly asks for that level of detail.
5. Report the feature count, sprint count, key product decisions, and exclusions.

Acceptance criteria should be observable from a user's perspective, such as: "The user can mark an item as low stock and it appears in the buy list."
