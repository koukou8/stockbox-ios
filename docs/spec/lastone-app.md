# LastOne（仮称）仕様書

## 概要

家庭の日用品・食品・ペット用品などのストックを、最小の入力で管理する iOS アプリ。
「在庫数を正確に数えて記録する」ことをユーザーに要求せず、**残り1つになった瞬間にワンタップでチェックする**二値方式を基本とすることで、既存の在庫管理アプリが陥る「入力が面倒 → 実際の在庫とズレる → 使われなくなる」という失敗パターンを回避する。買い忘れと重複購入を防ぐことがゴール。

## ターゲットユーザー

- 家庭の買い出しを担う個人（一人暮らし〜夫婦・家族世帯）
- 在庫管理アプリを「入力が面倒で」使わなくなった経験のある人
- MVP は単独利用（1人1端末で完結）
- 英語 UI を基準としグローバル配信を視野に入れる（日本語にも対応）

## 設計思想

- **入力コストの最小化**: ユーザーの日常操作は原則 2 タップのみ
  1. 「残りわずか」チェック（ストックの最後の1つを開封したとき）
  2. 「買った」チェック（買い物リストのアイテムを購入したとき）
- **カウントは開封イベントに紐づける**: カウント方式でも「使うたびに減らす」ではなく「新しい1つを開封したら −1」。物理的に手が止まる瞬間だけアプリを触る
- **ローカルファースト**: データは端末内で完結し、圏外（スーパーの店内・収納前など）でも全機能が動作する
- **データは初日から、UI は後から**: 購入履歴（PurchaseLog）は MVP 時点から記録する。カレンダー・消費周期予測などの将来機能の土台とする

## 多言語対応（i18n）

- **基準言語（開発言語）: 英語**。UI 文言はすべて String Catalog（`.xcstrings`）で管理し、ハードコードしない
- 対応言語: 英語 / 日本語
- 言語切替: 端末の言語設定に自動追従。加えて iOS 標準の「設定 > アプリごとの言語」で個別切替が可能（複数ローカリゼーションを含むアプリでは OS が自動提供、追加実装不要）
- アプリ内に独自の言語切替 UI を置くかは TBD（置く場合は Settings 画面に配置し `AppleLanguages` オーバーライドで実装）
- 日付表示（最終購入日など）はロケール準拠のフォーマッタを使用
- App Store メタデータ（説明文・スクリーンショット）も en / ja の両方を用意

## 主要機能

### 1. カテゴリ管理
- 初回起動時にプリセットを投入: 「Daily Goods」「Food」「Pet Supplies」など（ローカライズされたプリセット名）
- 自由に追加・編集・並べ替え・削除できる

### 2. アイテム登録（管理方式をアイテムごとに選択）
- **二値方式（デフォルト）**: 在庫数を持たない。「在庫あり ⇄ 残りわずか」の状態だけを管理
  - 例: 醤油・シャンプーなど「1つを長く使うもの」
- **カウント方式（任意でオン）**: ストック数と閾値（デフォルト 1）を持つ。開封時に −1 し、閾値以下になったら自動で「残りわずか」になる
  - 例: トイレットペーパー・おむつなど「複数ストックして順に消費するもの」

### 3. 買うものリスト（Buy List）
- 「残りわずか」状態のアイテムを自動集約
- 「買った」タップで:
  - 在庫状態を「在庫あり」に戻す（カウント方式は購入数を加算）
  - 購入日時を自動記録（PurchaseLog に追記 + Item.lastPurchasedAt を更新）

### 4. 最終購入日の表示
- アイテムカードに「最終購入日」を表示（例: "Bought Aug 15" / 「8/15 に購入」）
- 「これいつ買ったっけ？」に即答できる。既存競合（ストックシェア等）にない差別化ポイント

### 5. 購入履歴の蓄積（MVP では UI 非表示）
- 「買った」タップのたびに PurchaseLog へ記録
- 将来のカレンダー表示・消費周期予測・「切れる日予測」の学習データとなる

### 6. 無料枠の上限と Pro 解放
- 無料枠を超えるカテゴリ / アイテムを追加しようとした時点で Paywall を表示（詳細は「課金」参照）

## 課金（マネタイズ）

| 項目 | 内容 |
|------|------|
| モデル | 買い切り（non-consumable）「LastOne Pro」 |
| 無料枠 | カテゴリ 5 個・アイテム 30 個まで（数値は TBD） |
| Pro | カテゴリ・アイテム無制限 |
| 価格 | TBD（¥600〜1,000 / $4.99〜6.99 目安） |
| 実装 | RevenueCat（StoreKit 2）。entitlement `pro` で判定。Paywall は RevenueCat Paywalls で構築 |

- Paywall 表示トリガー: 上限超過の追加操作時。Settings からも購入導線を常設
- 「購入をリストア」ボタンを必ず設置（App Store 審査要件）
- プライバシーポリシー・利用規約の URL を用意（審査要件）
- 将来の消費周期予測機能はサブスクリプション課金の候補。買い切り Pro との関係はその時点で設計する

## 計測（アナリティクス）

PostHog で以下を計測する（イベント名は実装時に確定）:

- コアループ: `item_marked_low`（残りわずかチェック）/ `item_purchased`（買ったタップ）/ `item_opened`（開封 −1）
- 定着: `item_created` / `category_created` / アプリ起動（自動計測）→ リテンション分析
- 課金ファネル: `paywall_shown` → `pro_purchased`
- App Store プライバシーラベルの申告対象（PostHog / RevenueCat とも SDK にプライバシーマニフェスト同梱）

## データモデル

```
Category 1 ─── N Item 1 ─── N PurchaseLog
```

SwiftData の `@Model` クラスとして実装する。

### Category
| フィールド | 型 | 説明 |
|-----------|----|----|
| id | UUID | |
| name | String | カテゴリ名 |
| sortOrder | Int | 表示順 |
| createdAt | Date | |

### Item
| フィールド | 型 | 説明 |
|-----------|----|----|
| id | UUID | |
| category | Category | リレーション |
| name | String | アイテム名 |
| trackingMode | 'binary' \| 'count' | 管理方式 |
| stockCount | Int? | カウント方式のみ使用 |
| threshold | Int | 「残りわずか」になる閾値（デフォルト 1、カウント方式のみ） |
| status | 'in_stock' \| 'low' | 在庫状態 |
| lastPurchasedAt | Date? | 最終購入日時 |
| sortOrder | Int | 表示順 |
| createdAt / updatedAt | Date | |

### PurchaseLog
| フィールド | 型 | 説明 |
|-----------|----|----|
| id | UUID | |
| item | Item | リレーション |
| purchasedAt | Date | 購入日時 |
| quantity | Int | 購入数（デフォルト 1） |

### 状態遷移

```
二値方式:
  in_stock ──「残りわずか」チェック──▶ low ──「買った」──▶ in_stock

カウント方式:
  stockCount を開封時に −1
    └─ stockCount ≤ threshold になったら自動で low
  low ──「買った」(+n)──▶ in_stock
```

> 備考: 将来「品切れ (out)」状態を分けたくなった場合に備え、status は文字列 enum とし拡張可能にしておく。

## 認証・データ保護

- MVP では認証なし。データは端末内（SwiftData）のみに保存する
- 機種変更: iOS の標準バックアップ（iCloud / 暗号化ローカル）にアプリデータが含まれるため概ね引き継がれる。加えて Settings のエクスポート/インポートで手動退避が可能
- 恒久対応として SwiftData + CloudKit 同期を v1.1 で検討（認証 UI 不要・バックエンド費用ゼロで複数端末対応できる）
